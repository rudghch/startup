# 파일함 서비스 (파일 올리기·내려받기)

우리 반 친구들과 아무 파일(PDF, 한글, PPT, 사진, 압축 파일 등)이나 올리고 내려받는 웹 서비스입니다.
이 폴더에서는 이 서비스만 다룹니다.

## 함께 일하는 사람
- 사용자는 초등학교 6학년 학생(또는 선생님)입니다. 쉬운 말로 짧게 설명하고, 어려운 용어는 풀어서 말해 주세요.
- 무엇을 바꿨는지, 어디를 눌러 보면 확인할 수 있는지 매번 알려 주세요.
- 요청이 애매하면 마음대로 정하지 말고 한 가지만 되물어 주세요.

## 서비스 이름
파일함 (2026-11-02, 선생님이 "파일 올리고 다운받을 수 있는 거 하나 만들어줘"라고 해서 만듦. 이름은 Claude가 임시로 붙임)

## 만드는 방식
- 설치 없이 브라우저에서 바로 열리는 웹 페이지 (`index.html` 한 파일).
- 로그인해야 들어감. 메신저·잉스타·dockmap과 같은 AWS 서버, 같은 계정(`messenger.token`). 계정은 `API_URL`에 물어봄.
- 파일은 같은 서버의 **파일함 기능(FilesApi)** 에 올림. 주소는 `index.html`의 `FILES_URL`. 서버 파일과 설명서는 공개 폴더 밖 `클로드코드\메신저-서버-준비\`(`server.yaml`, `서버-만들기.md`의 "파일함 켜기").
  - 원래 서버는 사진·영상만 받아서(`upload`가 `image/`·`video/`만 허락) 파일함 기능을 따로 더함 (2026-11-02).
  - `FILES_URL`이 비어 있으면 "아직 서버에 파일함 기능이 켜지지 않았어요" 안내만 나오고 올리기 버튼이 꺼짐.
- 올리는 순서: `upload`(이름·크기를 보내면 보관함에 바로 올릴 주소를 받음, 15분짜리) → 그 주소로 `PUT` (`Content-Type: application/octet-stream`, XMLHttpRequest로 진행 막대) → `save`(서버가 진짜 올라갔는지·50MB 넘는지 확인하고 목록에 적음). 여러 파일은 하나씩 차례로 올림.
- 목록 `files`: 최근 200개, 새것부터. 각 파일에 1시간짜리 내려받기 링크(원래 파일 이름으로 받아짐). 목록을 받은 지 50분(`LINK_MINUTES`)이 지나면 "받기"를 누를 때 목록을 새로 받아 새 링크로 받음.
- 지우기 `remove`: 내가 올린 파일만. 서버 표(`pk` = `FILE`)와 보관함(`file/…`)에서 함께 지움.
- 파일 이름에 나쁜 말(`BAD_WORDS`, 잉스타·dockmap과 같은 목록)이 있으면 올리지 않음.
- 로그인한 사람은 **누구나 모든 파일을 볼 수 있음** (공개 범위를 나누지 않음).
- 실제 서비스의 이름과 로고는 쓰지 않습니다.

## 학생들이 바꾸기 쉬운 곳 (`index.html`)
- `MAX_MB`: 파일 하나 크기 한도 (50MB). 서버(`server.yaml`의 `MAX`)도 함께 바꿔야 함
- `FILE_ICONS`: 파일 끝 이름(확장자)마다 보여 줄 그림
- `LINK_MINUTES`: 내려받기 링크를 새로 받을 때까지의 시간

## 지금까지 만든 것
(기능을 하나 완성할 때마다 여기에 한 줄씩 적기)
- 첫 버전 (2026-11-02): 끌어다 놓기 또는 "📎 파일 고르기"(여러 개)로 올리기, 진행 막대, 목록(그림·이름·크기·올린 사람·언제), "⬇ 받기", 내 파일 "삭제", 이름·올린 사람으로 찾기, "모든 파일/내가 올린 파일", "🔄 새로 보기". 처음 화면에 카드 더함
- 시험 (2026-11-02, 가짜 서버·가짜 보관함): 파일 2개 차례로 올리기와 진행 막대, 나쁜 말 이름 막기, 50MB 넘는 파일 막기, 찾기, 내가 올린 파일, 지우기, 오래된 링크를 누르면 목록을 새로 받아 새 링크로 가기를 확인함. 컴퓨터·핸드폰 크기 화면 확인
- 서버 켜짐 (2026-11-02): 선생님이 AWS 웹 화면에서 스택을 업데이트함. `FILES_URL` 넣음. 진짜 사이트에서 선생님 계정으로 `시험 파일.txt`(41바이트)를 올리고, 목록·받기 링크(`attachment; filename*=UTF-8''시험 파일.txt`, 1시간)·삭제까지 확인한 뒤 지움
- 바로 보기 (2026-11-03 선생님 요청 "올라온 파일 바로 클릭하면 바로 볼 수 있도록"): 목록의 그림·이름이나 "👀 보기"를 누르면 큰 창이 열림. 사진(png·jpg·gif·webp·bmp·svg)은 그림으로, 영상(mp4·webm·mov)·소리(mp3·wav·m4a·ogg)는 재생기로, PDF·글(txt·md·csv)은 창 안에 그대로 보여 줌. 한글·PPT·엑셀·압축 파일은 "브라우저에서 바로 열 수 없어요, ⬇ 받기" 안내. 창 위에 "↗ 새 창에서 크게"(핸드폰에서 PDF가 창 안에 잘 안 보일 때), "⬇ 받기", "✕ 닫기". 닫으면 영상·소리가 멈춤. 링크가 50분 넘게 오래되면 목록을 새로 받아서 염
  - 서버: `files`가 바로 보기 링크 `view`(inline, 알맞은 Content-Type)를 더 줌 (`server.yaml`의 FilesApi `V`, `link`). **선생님이 스택을 업데이트해야 켜짐**(`서버-만들기.md`의 "파일함 바로 보기 켜기"). 업데이트 전에는 사진·영상·소리만 바로 보이고 PDF·글은 "서버를 한 번 업데이트해야 해요" 안내가 나옴. 보관함(S3) CORS가 PUT만 허락해서 브라우저가 파일 내용을 직접 읽을 수는 없음
  - 시험: 가짜 서버로 사진·글·PPT·옛 서버 PDF·소리 5가지 창, 닫았다 바로 다시 열기("닫힘" 알림이 늦게 와서 새 내용을 지우던 문제 고침), 핸드폰 크기. 서버 코드는 브라우저 속 파이썬(Pyodide)으로 돌려 pdf·JPG에 view가 생기고 hwp·끝 이름 없는 파일에는 안 생기는 것을 확인함. 진짜 서버 업데이트 뒤 PDF 보기는 아직 확인 못 함
- 아직 확인 못 한 것: 받기 버튼을 눌러 진짜로 내려받았을 때 한글 파일 이름이 그대로 나오는지(링크 설정만 확인함), 큰 파일(수십 MB)과 핸드폰에서 올리기
