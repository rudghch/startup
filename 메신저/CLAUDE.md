# 메신저 서비스 (카카오톡과 비슷한 서비스)

초등학교 6학년 학생들이 직접 기획하고 만드는 메신저 웹 서비스입니다.
이 폴더에서는 메신저 서비스만 다룹니다.

## 함께 일하는 사람

- 무엇을 바꿨는지, 어디를 눌러 보면 확인할 수 있는지 매번 알려 주세요.
- 요청이 애매하면 마음대로 정하지 말고 한 가지만 되물어 주세요.

## 만드는 방식
- 설치 없이 브라우저에서 바로 열리는 웹 페이지로 만듭니다 (HTML, CSS, JavaScript).
- 계정과 대화, 게시물은 AWS 서버에 저장합니다. 그래서 다른 컴퓨터의 친구와도 주고받을 수 있습니다.
- 한 번에 기능 하나씩 만들고, 동작을 확인한 뒤 다음 기능으로 넘어갑니다.
- 실제 서비스의 이름과 로고는 쓰지 않습니다. 서비스 이름은 학생들이 정합니다.
- 실제 이름, 전화번호, 사진 같은 개인정보는 넣지 않습니다. 친구 이름은 지어낸 이름을 씁니다.

## 지금까지 만든 것
(기능을 하나 완성할 때마다 여기에 한 줄씩 적기)
- 대화창: 메시지를 쓰고 보내기 버튼이나 엔터로 보냄 (`index.html` 한 파일)
- 계정: 아이디(2~12글자 별명)와 비밀번호(4글자부터)로 가입하고 로그인함. 가입할 때 선생님이 정한 가입 코드가 필요함. 로그인은 그 브라우저에 기억되고 "로그아웃"으로 나감
- 계정별 대화: 모든 계정이 대화방 하나에 함께 참여함. 내 메시지는 오른쪽, 다른 계정 메시지는 왼쪽. 3초마다 서버에 새 메시지를 물어봄
- 게시물: 글과 사진·영상을 올리고, 내가 올린 것만 삭제함. 사진은 1280px로 줄이고 영상은 30MB까지, 파일은 6개까지
- 서버: AWS(Lambda + DynamoDB + S3)를 씀. 서버를 만드는 파일과 설명서는 공개 폴더 밖인 `클로드코드\메신저-서버-준비\`에 있음 (`server.yaml`, `서버-만들기.md`). 계정 주인이 AWS 화면에서 직접 만들어야 하고, 나온 서버 주소(ServerUrl)를 `index.html`의 `API_URL`에 넣으면 연결됨. 주소가 비어 있으면 "서버가 아직 연결되지 않았어요" 화면이 나옴
- 서버는 잉스타(사진공유)와 함께 쓸 수 있게 만들었음 (게시판 이름 `board`만 다르게 보냄). 잉스타 연결은 사진공유 폴더에서 따로 함
- 서버 만든 날: 2026-10-06, AWS 서울 지역, CloudFormation 스택 이름 `messenger`. 서버 주소는 `index.html`의 `API_URL`에 넣어 둠. 가입 코드는 학생이 직접 정했고 Claude는 모름 (묻거나 파일에 적지 않기)
- 진짜 서버에서 확인한 것: 서버 연결, 틀린 로그인 막기, 틀린 가입 코드 막기, 로그인 안 한 사람 막기. 아직 확인 못 한 것: 진짜 가입, 대화 주고받기, 사진·영상 올리기 (가입 코드가 있어야 해서 학생이 직접 해 봐야 함)
- 미리보기: 작업 폴더의 `.claude/launch.json`에 있는 `startup-preview`로 열고 `http://localhost:8765/메신저/`로 감 (파일을 그냥 열면 버튼이 동작하지 않는 멈춘 화면만 보임)

- 학생이 "올려줘"라고 하면 이 폴더의 변경만 GitHub에 올립니다. 다른 팀 폴더는 건드리지 않습니다.

  - `git`을 찾지 못하면 `C:\Program Files\Git\cmd\git.exe`를 씁니다.
- 올린 뒤 1~2분 지나면 크롬북에서 새로고침해 확인할 수 있습니다.
  - 주소: https://rudghch.github.io/startup/메신저/
- 올리기 전에 실제 이름, 얼굴 사진, 전화번호 같은 개인정보가 없는지 확인합니다. 이 사이트는 누구나 볼 수 있습니다.- 서비스 이름을 message로 정함 (화면 제목과 처음 화면 카드. 폴더와 주소는 그대로 `메신저`)
- 나쁜 말 가리기: `index.html`의 `BAD_WORDS`에 적힌 욕설·비속어를 대화와 게시물 글에서 `###`로 바꿈. 보낼 때 가려서 저장하고, 보여 줄 때도 한 번 더 가림. 글자 사이에 숫자나 기호를 끼워도 찾음. 아이디에는 아직 적용하지 않음

- 이동 링크: 로그인한 뒤에도 맨 위 오른쪽에 "처음 화면"과 "잉스타"로 가는 링크가 보임 (잉스타에도 "처음 화면"과 "message" 링크를 넣음)
- 프로필 사진 (2026-10-06): 맨 위 오른쪽의 내 아이디 버튼을 누르면 프로필 사진을 고르거나 기본 그림(아이디 첫 글자)으로 되돌림. 대화의 친구 이름 옆, 게시물, 맨 위에 프로필 사진이 보임. 잉스타와 같은 게시판(`instarprofile`)을 써서 두 곳에 같은 사진이 보임. 30초마다 새로 받아 옴
- 대화에 사진·영상 넣기 (2026-10-06): 입력칸 왼쪽 📷 버튼으로 사진·영상을 6개까지 골라 글과 함께 보냄 (영상 30MB까지). 서버는 고치지 않음: 파일은 1시간마다 바뀌는 게시판(`cm`+시간 번호를 글자로 바꾼 것)에 올리고, 메시지 끝에 `[[file:게시판:i.사진이름,v.영상이름]]` 꼬리표를 붙여 보냄. 한 게시판에서 100개까지만 받아 오므로 1시간에 사진·영상 메시지가 100개를 넘으면 오래된 것은 안 보일 수 있음
- 아직 확인 못 한 것: 프로필 사진과 대화 속 사진·영상을 진짜 서버에서 써 보는 것 (화면은 가짜 서버로만 시험함)
- 대화방 (2026-10-06): 대화 화면에 처음 들어오면 대화방 목록이 나옴. "모두의 대화방"은 로그인한 모두가 들어오는 원래 대화방. 그 밖에 누구나 새 대화방을 만들 수 있고, 만든 사람(방장)이 "👥 사람" 창에서 아이디로 초대하거나 내보냄. 초대받은 사람은 "나가기", 방장은 "대화방 없애기"를 할 수 있음. 내보내지면 다음 확인 때(3~10초) 목록으로 돌아감. 만든 대화방에서는 글과 사진·영상을 서버가 함께 저장함
- 대화방 서버: `클로드코드\메신저-서버-준비\server.yaml`에 두 번째 서버 프로그램(`RoomsApi`)을 더함. 서버가 대화방 사람인지 확인하므로 초대받지 않은 사람은 메시지를 못 봄. 주소(`RoomsUrl`)를 `index.html`의 `ROOMS_URL`에 넣어야 켜짐. 비어 있으면 "모두의 대화방"만 보이고 만들기 칸은 숨겨짐
- 대화방 서버 켠 날: 2026-10-06 (스택 업데이트 완료, `ROOMS_URL` 넣음). 진짜 서버에서 확인한 것: 대화방 서버 연결, 로그인 안 한 사람 막기. 아직 확인 못 한 것: 진짜로 대화방 만들기·초대·내보내기·사진 보내기 (로그인이 필요해서 학생이 직접 해 봐야 함. 화면은 가짜 서버로만 시험함)
